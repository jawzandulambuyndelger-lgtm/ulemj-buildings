# ULEMJ BUILDINGS

Монгол хэл дээрх олон хуудаст, responsive Next.js вебсайт. Next.js App Router, React, TypeScript, Tailwind CSS, Lucide ашиглав.

## Ажиллуулах

Node.js 20.9+ шаардлагатай.

```powershell
cd ulemj-buildings
npm install
npm run dev
```

Хөтчөөр `http://localhost:3000` хаягийг нээнэ. Production хувилбар:

```powershell
npm run build
npm start
```

`.env.example` файлыг `.env.local` болгон хуулж, бодит домэйныг `NEXT_PUBLIC_SITE_URL` утгад оруулна. Нийтлэх домэйныг өөрчилсний дараа дахин build хийнэ.

- Брэнд, төрөл, материал, зориулалтаар хослуулан шүүх каталог; төслийн ангилал; холбоост хадгалагдах шүүлтүүр.

- Хувийн мэдээлэл, зөвшөөрөл, имэйл, утас болон төслийн мэдээллийн клиент/сервер шалгалт.

## Маягтын өнөөгийн ажиллагаа

**Ямар нэг имэйл эсвэл CRM үйлчилгээ автоматаар холбогдоогүй.**

Үндсэн горимд маягт мэдээллийг шалгаж, монгол текст хүсэлтийн файл татаж өгнө. Хэрэглэгч файлаа, зураг төслийн хавсралтуудаа өөрөө `info@ulemj.mn` хаягт илгээнэ. `Имэйл бэлтгэх` холбоос нь зөвхөн тухайн хэрэглэгчийн имэйл программыг нээнэ. Файлууд автоматаар имэйлд хавсардаггүй. Энэ горимд мэдээллийг API руу илгээхгүй, localStorage-д хадгалахгүй, амжилттай илгээгдсэн гэж мэдээлэхгүй. `/api/inquiries` нь тохиргоогүй үед 503 буцаана.

### Бодит хүлээн авах үйлчилгээг холбох

1. Компанийн хяналтад байдаг HTTPS endpoint бэлтгэнэ.
2. `.env.local` эсвэл deployment орчинд дараах утгыг тохируулна:

```dotenv
INQUIRY_WEBHOOK_URL=https://your-service.example/inquiries
INQUIRY_WEBHOOK_TOKEN=your-server-side-token
INQUIRY_DELIVERY_ENABLED=true
```

3. Endpoint нь `multipart/form-data` хүлээн авна. `inquiry` нь JSON текст; `files` нь давтагдах файлын талбар. JSON нь `kind` (`quote`/`contact`), нэр, утас, имэйл, тайлбар, зөвшөөрөл, төслийн сонголтууд болон `submittedAt` агуулна. `Authorization: Bearer …` болон `Idempotency-Key` header дамжуулна.
4. Endpoint зөвхөн хүсэлтийг **бодитоор хадгалсан/хүлээн авсан** үед 2xx буцаана. Дахин оролдлогыг `Idempotency-Key`-ээр давхардуулахгүй боловсруулна. Дараа нь компанийн бодит inbox/CRM-д хүрсэн эсэхийг шалгана.
5. Илгээлтийн үйлчилгээ, хадгалалтын хугацаа, мэдээлэл хариуцагчийг нууцлалын хуудсанд шинэчилж, production орчинд form submit-ийг шалгана.

`src/lib/delivery.ts` дэх `InquiryRepository` интерфэйсийг Firebase/database adapter-аар сольж болно. Token клиент кодод гарахгүй. API нь origin, body хэмжээ, Zod schema, файлын өргөтгөл/хэмжээ/давхардал болон файлын эхний signature-ийг шалгана. Хязгаар нь stream унших явцад бас хэрэгжинэ. Нэг process-ийн түр rate limit бий; production дээр платформ/WAF-ийн rate limit, итгэмжлэгдсэн proxy header болон хортой файл шалгах үйлчилгээг хүлээн авагч талдаа тохируулна. Хувийн мэдээлэл/файлыг серверийн диск эсвэл log-д бичихгүй.

## Агуулгыг засах

Бүх компанийн өгөгдөл, үйлчилгээ, брэнд, бүтээгдэхүүн, төсөл, жишиг өнгө: `src/lib/data.ts`.

Жинхэнэ бүтээгдэхүүний PDF-ийг `public/catalogs/` хавтаст оруулаад тухайн бүтээгдэхүүний `catalog` утгад `/catalogs/filename.pdf` гэж холбоно. `catalog: null` үед хуурамч download үүсгэхгүй, каталог хүсэх холбоос гарна. Зөвшөөрөгдсөн бүтээгдэхүүний зураг, баталгаат техникийн үзүүлэлт болон өнгийг мөн өгөгдөлд нэмнэ.

Төслийн `gallery` талбарт `{ src: '/images/projects/photo.jpg', alt: 'Бодит зургийн тайлбар' }` объектууд нэмэхэд бодит зургууд, томруулдаг gallery автоматаар ажиллана. `location`, `scope`, `materials`-ийг баталгаат мэдээллээр бөглөнө. Зураггүй үед жинхэнэ барилгын зураг мэт харуулахгүй, тодорхой тэмдэглэсэн бүдүүвч үзүүлнэ.

`company.address` болон `company.businessHours` одоогоор `null`. Баталгаатай мэдээллээр солих ба contact map-ийн жинхэнэ pin/embed-ийг тухайн үед нэмнэ.

Баталгаажуулах агуулга, зургийн эх сурвалж: [CONTENT.md](./CONTENT.md).

## Шалгалт

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Суулгасан Google Chrome-оор турших бол PowerShell дээр `$env:PLAYWRIGHT_CHANNEL = 'chrome'` гэж тохируулаад `npm run test:e2e` ажиллуулж болно.

Playwright нь production build-ийг 3100, 3101 портуудад туршилтаар ажиллуулна. 3100 нь холбоогүй горим, 3101 нь илгээлт идэвхтэй UI-г **mock хариугаар** шалгах орчин. Бодит имэйл, CRM руу мэдээлэл илгээхгүй. Route, filter, marble, quote handoff, файл, validation, draft download, error/success, гар утасны навигаци, responsive overflow болон axe accessibility шалгалт орно. Жишиг screenshot-ууд `qa/` хавтаст үүснэ.

Бодит илгээлтийн endpoint, компанийн хэрэглэгчийн inbox эсвэл албан ёсны PDF файлуудыг энэ хувилбарын туршилт баталгаажуулаагүй; тэдгээрийг холбоход тусад нь шалгана.
